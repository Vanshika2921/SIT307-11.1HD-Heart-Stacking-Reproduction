# SIT307 11.1HD — Reproducing a Stacking Ensemble for Heart Disease Prediction

This repository contains the Jupyter notebook, dataset, and generated results/figures for the
Deakin SIT307 11.1HD research task: reproducing the stacking-ensemble experiment described in

> M. Bhagat, A. Sharma, and P. Agarwal, "An efficient stacking-based ensemble technique for
> early heart attack prediction," *Multimedia Tools and Applications*, vol. 84, pp. 36351–36375,
> 2025, doi: [10.1007/s11042-024-19293-7](https://doi.org/10.1007/s11042-024-19293-7).

The publisher's paper PDF is not included here (copyright); see the DOI link above.

## Dataset

- **Source:** JohnSmith88, "Heart Disease Dataset," Kaggle.
  <https://www.kaggle.com/datasets/johnsmith88/heart-disease-dataset>
- Provided in this repo at [`data/heart.csv`](data/heart.csv) — 1,025 rows, 14 columns (this is
  the exact CSV used to produce every result in `results/` and `figures/`).
- The dataset contains 723 exact duplicate rows (a known property of this Kaggle release, not an
  error introduced by this project); the notebook's Part 1 analysis explicitly investigates this,
  including the 202/205 train/test row-overlap check discussed in the accompanying report.

## What this notebook does

- **Part 1:** Data loading, duplicate-row analysis, a train/test split leakage check (how many of
  the test rows are exact duplicates of a training row), and baseline individual classifiers
  (Logistic Regression, Decision Tree, Random Forest, Naive Bayes, k-NN, XGBoost).
- **Part 2:** A `StackingClassifier` ensemble evaluated with `RepeatedStratifiedKFold`, including a
  leakage-safe repeated cross-validation comparison against the published paper's reported
  accuracy.

## Environment setup

Tested with **Python 3.11.16** on Windows. From the repository root:

```bash
python -m venv .venv
.venv\Scripts\activate        # on Windows
# source .venv/bin/activate   # on macOS/Linux
pip install -r requirements.txt
```

The exact package versions in [`requirements.txt`](requirements.txt) were confirmed — by
re-running this notebook from a clean environment — to reproduce every file in `results/` and
`figures/` byte-for-byte. Using different major versions (in particular of `xgboost` or `pandas`)
can shift the last few results in Part 2's repeated cross-validation, since XGBoost's internal
tree-building changed across major versions.

## Running the notebook

Launch Jupyter and run all cells from top to bottom:

```bash
jupyter notebook SIT307_11.1HD_Heart_Stacking.ipynb
```

or execute it headlessly:

```bash
jupyter nbconvert --to notebook --execute --inplace SIT307_11.1HD_Heart_Stacking.ipynb
```

The notebook reads `data/heart.csv` and writes to `results/` and `figures/`. A small setup cell
(cell 2, clearly marked with a comment `# --- setup: ensure output folders exist ... ---`) was
added right after the imports so that `data/`, `results/`, and `figures/` are created
automatically on a fresh clone if they don't already exist — no other code was changed from the
originally executed notebook.

## Generated files

| File | Description |
|---|---|
| `results/individual_model_results.csv` | Accuracy/precision/recall/F1/AUC/MCC for each individual baseline model (Part 1). |
| `results/reproduction_all_models.csv` | Combined reproduced results for all models, including the stacking ensemble. |
| `results/published_vs_reproduced.csv` | Side-by-side comparison of the paper's published metrics against this reproduction. |
| `results/repeated_cv_leakage_safe.csv` | Per-fold results of the leakage-safe `RepeatedStratifiedKFold` evaluation (Part 2). |
| `results/final_stacking_summary.csv` | Final summary of the stacking ensemble's repeated-CV accuracy (mean ≈ 0.8298). |
| `figures/final_stacking_accuracy_comparison.png` | Bar chart comparing published vs. reproduced stacking accuracy. |

All of the above were generated by actually executing the notebook — none of these numbers were
invented or edited by hand.
